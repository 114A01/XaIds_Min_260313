# XaIDS 使用手冊（精簡版）

> 給第一次使用系統、或要上台 demo 的人。讀完約 10 分鐘，就能把系統跑起來並看懂畫面。
> 原理、評審問答、交接事項在 [manual_full.md](manual_full.md)。內容以 2026-11-17 的程式為準。

## 1. 這個系統在做什麼

XaIDS 是一個「可解釋的入侵偵測」展示系統。對每一條網路連線（flow），它做三件事：

1. 用 XGBoost 模型判斷這條連線屬於 7 類中的哪一類（Benign、BruteForce、DoS、Mirai、Recon、Spoofing、Web-based），並給出信心值。
2. 用 SHAP 和 LIME 兩種方法各解釋一次「模型為什麼這樣判」。
3. 比較兩份解釋像不像，得到「解釋一致性」分數，並以燈號顯示。

研究問題是：**兩個解釋器意見一致，能不能當作「這筆警報可以相信」的依據。**
系統本身是展示工具，不會阻擋攻擊。

## 2. 啟動

```bash
conda activate MLEnv
cd <專案根目錄>                       # 一定要在專案根目錄執行
uvicorn api.main:app --reload --port 8080
```

看到 `Application startup complete.` 後，用瀏覽器開 `http://localhost:8080`。

- CSV 重播預設讀 `data/csv/`，裡面是淨化過標籤的測試集（檔名 `ciciot2023_cleaned_*.csv`），直接用即可。要改用別的目錄時，啟動前加 `XAIDS_DATA_DIR=<目錄>`。pcap 重播與即時擷取不受這個設定影響。
- 第一次在新機器上使用，要先安裝套件並建立資料庫帳號，步驟在詳細版 2.1、2.2 節。
- MariaDB 要先啟動。資料表還沒建，或想清空全部資料時執行下面這行（**會刪掉所有測試紀錄**）：

```bash
mariadb -u allen -pallen xaids < db/xaids_schema.sql
```

## 3. 頁面一覽

| 頁面 | 用途 |
|---|---|
| 首頁 `/` | 系統狀態、目前模型、類別與特徵 |
| 測試 `/test` | 開始一次測試（run）：重播 CSV、重播 pcap 或即時擷取，即時看每條 flow 的結果 |
| 展示 `/demo` | 給觀眾看的畫面：目前分析狀態、最新 flow、帶一致性燈號的警報列表，會自動更新 |
| 歷史 `/history` | 勾選幾次測試，合併看五張統計圖；下方是所有測試的列表 |
| 單次測試 `/history/{id}` | 同樣的五張圖，只看那一次，另有每條 flow 的明細 |
| 單筆解釋 `/explain/{id}` | 一條 flow 的 SHAP、LIME 與一致性細節 |
| 流量紀錄 `/packetRecord` | 最近 500 條 flow |

## 4. 跑第一次測試（約 1 分鐘）

1. 開「測試」頁，來源選 **pcap 重播**，檔案選 `syn-flood_1110.pcap`。
2. 「預期標籤」選 `DoS`，「最多處理筆數」填 `100`，「LIME 重複次數」填 `3`。
3. 按 **開始測試**。下方表格每一列是一條 flow，會一列一列出現，約 50 秒跑完。
4. 點任一列右邊的 **Explain**，看這條 flow 的 SHAP 與 LIME 解釋。
5. 開「歷史」頁，上方勾選剛才那次測試，看統計圖。

測試進行時開「展示」頁，可以看到同一批結果即時出現。同一時間只能跑一個測試。

## 5. 看懂畫面需要的五個詞

| 詞 | 意思 |
|---|---|
| **信心值** | 模型對自己預測的類別給的機率，0% 到 100% |
| **ZONE** | 依信心值與類別分四區。`UNCERTAIN`：信心值低於 60%。`BENIGN`：判為正常且信心值 ≥ 60%。`SUSPICIOUS`：判為攻擊，信心值 60% 到 85%。`HIGH_CONF`：判為攻擊，信心值 ≥ 85%。後兩種會產生警報 |
| **TOP-K** | 比較兩份解釋時，各取最重要的前 k 個特徵。k 可選 3、5、7，預設 5 |
| **一致性** | 兩份解釋的前 k 個特徵中，「同時出現而且影響方向相同」的有幾個。k = 5 時範圍是 0 到 5 個，畫面上也會以百分比顯示（3 個 = 60%） |
| **燈號** | ● 綠燈「可信」：一致性 ≥ 60%。◐ 黃燈「建議人工檢查」：30% 到 60%。○ 紅燈「解釋不一致」：低於 30%。門檻是暫定值 |

## 6. 歷史頁的五張圖

| 圖 | 橫軸 | 看什麼 |
|---|---|---|
| ① 一致性 × 筆數 | 一致的特徵數（0 到 k） | 一致性的分布；顏色分「分類正確 / 錯誤」 |
| ② 一致性 × 正確率 | 同上 | 一致性越高，模型是否越常判對；虛線是整體正確率 |
| ③ 信心值 × 筆數 | 信心值區間 | 信心值的分布；顏色分「一致組 / 不一致組」 |
| ④ 信心值 × 正確率 | 同上 | **最重要的一張**：同一個信心值區間內，一致組（綠）是否比不一致組（紫）更常判對 |
| ⑤ 一致性 × 信心值 | 一致的特徵數 | 每個點是一條 flow，看一致性和信心值是不是同一回事 |

圖上方的摘要列有整體正確率、平均一致特徵數、兩組錯誤率、AUROC 等數字。

## 7. 最常遇到的狀況

| 狀況 | 原因與處理 |
|---|---|
| 頁面怪怪的、新功能沒出現 | 瀏覽器拿到舊的頁面，按 `Ctrl+Shift+R` 強制重新整理 |
| CSV 按開始後顯示「缺少特徵欄位」 | CSV 目錄不是 22 特徵的檔案。確認沒有把 `XAIDS_DATA_DIR` 指到舊資料，拿掉它重新啟動即可回到預設的 `data/csv/` |
| 即時擷取開始後一直沒有資料 | 正常。一條 flow 要閒置 30 秒或持續 60 秒才會送出分析 |
| 攻擊類 CSV 的正確率只有個位數 | 不是模型壞掉。原始 CSV 把「攻擊期間錄到的所有連線」都標成攻擊，其中大部分其實是背景流量。詳細版 6.3 節有說明，demo 時不要用這個數字代表模型表現 |
| 「刪除」按了沒反應 | 刪除要按兩下：第一下變成「再按一次確認刪除」，5 秒內再按一次 |
| 按開始卻顯示已有測試在執行 | 同一時間只能跑一個，先按「停止」 |
| 伺服器重啟後測試狀態變成 stopped | 正常。執行中的測試不會跨重啟續跑，已分析的資料都還在 |
| 歷史頁打開時舊的測試沒有被勾選 | 正常。它們是其他模型或舊的 SHAP 設定跑的，預設不混進統計 |
